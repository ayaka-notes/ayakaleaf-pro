# Bug hunt — BibTeX visual editor + Library

2026-11-05 · scoped to `services/web/modules/bib-editor` (parser, writers, validation, diagnostics, preview/list model, preview session, Library front+back end, import paths, serializers).

Method: adversarial probes against the real modules (regression suite in
`test/unit/src/bug-hunt-probes.test.mjs`, 23 tests), line-by-line review of
the server library stack and both provider serializers. Findings grouped by
severity; every fix is tested.

## Fixed (this session)

### H1 · Library downloads could produce unparseable BibTeX
`app/src/LibrarySerializer.mjs` `escapeBibValue` tracked brace depth but wrote
an unmatched `{` through unescaped (`a{b` → `title = {a{b}`, broken output).
Same stale port as the editor-side bug fixed in #6.
**Fix:** both serializers now use the shared brace-safe algorithm (balanced
groups kept, stray `}` escaped, unmatched `{` escaped, already-escaped
preserved). Round-trip verified through the real parser.
- `app/src/LibrarySerializer.mjs` (library "Download" endpoint)
- `deps/mendeley/app/src/MendeleyBibtexSerializer.mjs` (Mendeley API fallback,
  which interpolated raw values into braces)

### H2 · Renaming a library entry was silently dropped
`library-page.tsx` `flushPreview` called `saveEntry(rowId, originalKey,
{type, fields})` **without `key`** — the server kept the old key, so the form
showed the rename as saved but nothing changed. (The form even blocks
submitting with *empty* key, which made the bug visible as "renamed, then
reverted".)
**Fix:** flush ships `key: report.entry.id.trim() || undefined` (cleared key →
server keeps original, per key-required invariant; renamed key → persists).

### H3 · Duplicate-key rows could be updated/renamed to the WRONG row
The whole write API is keyed by citation key; when a library (or imported
batch) legally holds two rows with the same key, `PATCH /library/references/`
*key* could hit the wrong `_id`.
**Fix (row-precise addressing):**
- `library-api.ts` `updateEntry(originalKey, entry, targetRowId?)` sends
  `_id` when the row has one (24-hex ObjectId check client-side).
- `app/src/LibraryController.mjs` extracts `body._id`;
- `app/src/LibraryManager.mjs` `updateReferenceEntry` prefers `_id` (scoped by
  user + active), falls back to key when absent/invalid. Collision checks
  already excluded the target doc (`_id != doc._id`), so renames within a
  duplicate pair now behave sanely.
- `library-context.tsx` `saveEntry` forwards `rowId`; `library-page.tsx`
  passes the currently-open row's `_id` (falls back to key).

### H4 · Single delete of a duplicate key was a lie
`planBibDelete` rejected duplicate-key entries as `entry-gone` ("the file
changed…"), and `planBibBulkDelete` rejected ANY id that resolved to more
than one entry — both misleading.
**Fix (honest semantics, tested):**
- Single delete → explicit `duplicate-key` reason; the panel banner now
  explains it (new i18n key) and points at the Delete bulk action.
- Bulk delete → deletes **all occurrences** of each selected id (consistent
  with the checkbox model, where every row of a duplicate key is checked at
  once). All-or-nothing on *absence* is preserved.

### H5 · Escaped quotes truncated bare-quoted field values
`bib-parser.ts` `parseFields` closed a quoted value at the FIRST `"` —
`note="he said \"hi\""` parsed `note` as `he said \` and mangled the rest of
the entry (sibling fields could be lost).
**Fix:** backslash-aware closing-quote scan (`\"` no longer terminates).
Raw-value model preserved (the backslash stays in the value and round-trips).

### H6 · 409 duplicate-key body shape mismatch
`library-api.ts` read `body.info.duplicateKey`; the server emits
`{ message, duplicateKey }` at the top level. The duplicate-detected branch
of `importEntries` could never fire.
**Fix:** client accepts both shapes (top-level first).

### H7 · Dead "Next" at the end of the loaded page
`canNext` was enabled when `nextCursor != null`, but `stepPreview(1)` at the
last visible row was a no-op — an enabled button that did nothing.
**Fix:** `stepPreview` at the page end triggers `loadMore()` (list extends;
the second Next advances).

### H8 · Visual `.bib` panel crashed on every render (caught by live smoke)
`diagnosticsInfo` in the panel aggregated with `byEntry.values().flat()` —
`byEntry` is a `Map`; `.values()` is an iterator with no `.flat()`, so the
panel fell into its error boundary ("Something went wrong loading the
bibliography editor"). The pure-utils vitest suite never covered the
panel's expression; the live browser test caught it.
**Fix:** `allDiagnostics()` helper + 2 regression tests (commit `202fbb8e07`).

### H9 · Library bulk Download button was dead
`BibEntryList` renders the library bulk bar (Download + Delete) and the
server endpoint (`GET /library/references/download?ids=…`) existed, but
`library-page.tsx` never passed `onBulkDownload` — selection showed a
Delete-only bar. **Fix:** `handleBulkDownload` ships the selected ids;
verified live: 2-row selection → `library.bib` with exactly those entries,
round-trips through the editor parser (commit `42b71e76dc`).

## Verified NOT bugs (documented contracts / parity — now tested)

- **Keyless pasted entries are rejected on import** — parity with the
  reference (materializing keys for keyless docs requires the user's
  naming-rule context; the form materializes keys via deterministic
  generation for *existing* keyless entries). Probe locks the contract.
- **`hasValidBiblatexDate('2020-13')` → true** — month range is not checked
  anywhere in the module (syntax only); `year` format check likewise does
  not block. Documented + probed.
- **Navigation is index-based (`nextEntry(entries, index)`)**, which makes it
  duplicate-key-safe (both `dup` rows reachable, wraps correctly).
- **Preview session store** never throws on hostile `localStorage` payloads;
  malformed `listPosition` drops the whole session (documented validation).
- **Search normalization** is identical client↔server
  (`library-model.ts` vs `LibrarySearch.mjs`): lowercase, NFKC-ish trim,
  `\s+`→` `, split, drop empties, join.
- **Race safety:** `fetchPage` guards stale cursors (`cursor !==
  cursorRef.current`); `_id` identity is preserved for duplicate keys.
- **Routes** require login + library middleware; rate limits on import,
  search, download; `userId` always from `req.userId`, never client body.
- **`escapeBibValue` idempotence** (editor + both provider serializers).
- **Bulk ops are all-or-nothing**; bulk import is atomic
  (`planBibImport` + `planBulkWrite`).
